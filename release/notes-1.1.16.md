# v1.1.16

修 v1.1.15 里扫码配对的两个问题（独立复审提出，都是真的）：

## 1. 对面明确答复时不再乱换地址

v1.1.15 让手机按顺序试二维码里的多个地址，但判断「要不要换下一个」时看的是错误文案里有没有
`HTTP ` —— 而「配对码不对」「电脑上关掉了允许连接」「试错太多次」这三句话里都没有 `HTTP `，
于是被当成「连不上」，把**同一个一次性配对码**又往别的地址发了一遍。

- 现在改成结构化判断：`Pairing.claim()` 只要收到服务器响应就抛 `PairError`（带状态码），
  `claimAny()` 见到它就立刻停，把「配对码不对，还能试 N 次」这类真正的答复交给界面；
  只有「根本没连上」（超时 / 连接被拒 / DNS）才换下一个地址。
- 效果：码填错时你看到的是「配对码不对」，而不是含糊的「连不上这台电脑」。

## 2. 二维码里的备选地址给公网隧道留位

备选上限是 4 个，而公网隧道排在所有网卡之后 —— 网卡多的机器（Clash / Docker / WSL / 虚拟机）
会把隧道挤出列表，正好赶上「所有网卡都到不了」的情况就没路可走了。

- 现在隧道固定占一个位置：网卡最多占 3 个，剩下的给隧道。

## 安装

- 手机：`dsh-mobile-1.1.16-signed.hap`，覆盖安装。
- 电脑：插件需要重启 DSH 才吃到新的配对逻辑（本版 zip 与 GitHub 仓库都已同步 1.1.16 的构建）。
